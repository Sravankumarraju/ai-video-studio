# Provider adapter guide

Earlier contract-only verification notes reflect the initial implementation.

**Save and check connection** saves the encrypted profile and immediately runs a read-only check. Existing profiles also have **Check without generation**. ElevenLabs checks model discovery and the selected default voice independently, showing permission or voice-access guidance on the profile card. These checks never generate audio or establish speech-generation permission; live audio remains unverified until an explicitly authorized generation succeeds.

Owners can enter and replace API keys directly in **AI Providers → Add provider profile**. The **Set up ElevenLabs voice** shortcut fills the official base URL, voice capability and `eleven_v4` model. Enter the key privately, enter an accessible voice ID, and choose **Save encrypted profile**. No environment variable or restart is needed. Keys are encrypted in existing server storage; editing with a blank key preserves the current credential, and closing the form clears the unsaved key.

For ElevenLabs, enable Models read, Voices read and Text-to-Speech generation permissions in the provider account, and ensure the selected voice is available in My Voices. Choose **Check without generation** to check model discovery (this does not prove successful voice generation), then assign the profile under the voice capability default. Existing projects retain their provider choices; select the profile in that project's voice override or explicitly apply the saved defaults in project settings. Other capability defaults stay independently configurable. No schema migration is required.

`Adapter` defines capability discovery, generation, optional async polling, and voice listing. UI components only know profile IDs/capability metadata. Implement an adapter in `lib/providers.ts`, add its type to `providerSchema`, and register it in `registry`. Add isolated contract tests before enabling a capability in Settings.

Input includes frozen model/settings, prompt, language, duration, aspect, voice assignment and optional narration bytes. Results contain text, returned bytes, a validated download URL, or an async job ID. Async adapters must return their provider ID immediately; the worker persists it before polling. Poll results distinguish queued/running/succeeded/failed. Copy completed output to durable storage before exposing an asset.

Use the bounded, DNS-pinned `safeFetch` transport. Do not pass credentials into a prompt, asset metadata, client response, log or error. Secret-bearing parameters are rejected. Only parameter names explicitly marked supported in the profile are sent. Base URLs cannot hold query credentials. Generation errors are sanitized and carry HTTP status/ambiguous-submission classification. Preserve model-validation errors as actionable configuration messages.

ZenMux video uses `content: [{type:'text', text:prompt}]`, model, duration, ratio and optional documented supported parameters. It does not use a generic OpenAI video endpoint. Poll `content.video_url` after succeeded. The worker polls at the documented 15-second interval, at most 80 times per run, retaining the ID for resume. URL outputs and base64 image outputs are both imported.

ElevenLabs discovery checks `can_do_text_to_speech` and the selected model's `languages`, normalizing `tel`/`hin`/`eng` to the editor's `te`/`hi`/`en`. Legacy voice generation calls `/text-to-speech/{voiceId}/with-timestamps`. `eleven_multilingual_v2` does not receive `language_code`. Other models receive the selected language code; actual listed language support is required. Scene chunks pass previous/next narration for continuity. Returned character timing is grouped into phrase captions and complete words for optional highlighting. If timing is unavailable, the user can explicitly choose approximate or manually timed phrases.

`eleven_v4` and `eleven_v4_turbo` use the documented `/text-to-dialogue/with-timestamps` endpoint with one scene input and an explicit voice ID. The adapter limits each chunk to 2,000 characters, truncates surrounding-text context to 100 characters, and refuses legacy voice parameters rather than silently dropping them. Use an empty supported-parameter set for these profiles. Endpoint details: https://elevenlabs.io/docs/api-reference/text-to-dialogue/convert-with-timestamps . No persisted-schema migration is needed; existing profiles and jobs retain their selected models. Contract checks cover this endpoint; a live successful v4 generation is not yet verified. Keys need permission to read models and generate speech, and the voice must be accessible in the account. Model discovery permission failures and inaccessible voices must be resolved before narration generation.

OpenAI-compatible transcription uploads narration and requests verbose JSON. Providers/models must support this endpoint, selected language and response format. The worker validates returned timed segments. Model-specific endpoint support is never inferred from model-list membership. No adapter silently changes provider/model after a failure.

Publishing currently exports editable metadata and files only. Future platform adapters should define `authorize`, `prepare` and `publish` separately and require explicit human publication authorization; no upload/publish behavior is implemented or triggered now.
